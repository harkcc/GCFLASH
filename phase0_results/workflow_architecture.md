# Excitat 电商套图生成系统 — 完整工作流架构

**版本：v0.2 | 更新：2026-04-11**

---

## 一、总体流程概览

```
用户输入 → [素材评估] → [方案设计] → [品牌框生成] → [单图生成] → [AI评审] → [迭代/人审] → 输出套图
```

每个环节的详细逻辑如下。

---

## 二、Step 1 — 素材评估（Gemini 内容规划层）

### 输入
- 产品基础信息（名称、品牌、价格、卖点文案）
- 用户上传的产品图片（实拍白底图、场景图、细节图等）
- (可选) 竞品链接或竞品图片

### Gemini 做什么
Gemini 收到所有素材后，第一步不是生成 prompt，而是**评估素材完整度**：

```
评估维度：
├── 产品主体图：有没有？清晰度如何？角度是否足够（正面/侧面/45度/俯视）？
├── 细节/材质图：有没有？能否看清材质、按钮、接口？
├── 场景/使用图：有没有？有几种场景？
├── 品牌信息：Logo、品牌名、品牌色、品牌风格参考？
├── 文案信息：卖点、参数、标题、副标题？
└── 竞品信息：有没有竞品图？有没有目标平台？
```

### 三条分支路径

**A档（完整）→ 直接走全套设计**
- 条件：至少有1张清晰白底主图 + 3个以上卖点 + 品牌名
- 动作：进入 Step 2 全套方案设计

**B档（基本）→ 部分生成 + 缺失提示**
- 条件：有产品图但缺场景图/细节图/参数信息
- 动作：
  1. 先设计能做的图（hero、lifestyle、benefit）
  2. 返回缺失清单给用户：「缺少 USB-C 接口细节图，缺少产品尺寸信息」
  3. 用户补充后继续

**C档（最小）→ 网络寻图 + AI 补全**
- 条件：只有品牌名和产品名称，几乎没有图
- 动作：
  1. 搜索同类竞品图片作为风格参考（不直接使用，仅参考构图/角度/氛围）
  2. 纯 AI 生图（text-to-image），依赖 prompt 质量
  3. 标记这些图为「AI 纯生成，需人工确认产品外观准确性」

### Gemini 的评估 Prompt 模板

```
你是一个电商视觉内容策划专家。

我将提供一个产品的所有可用素材（图片+文案信息）。
请你评估这些素材是否足以支持生成一套完整的 7 张 Listing 图。

评估标准：
1. 产品主体可辨识性（1-10）
2. 卖点信息完整性（1-10）
3. 场景多样性（1-10）
4. 品牌元素完整性（1-10）

输出格式：
{
  "tier": "A/B/C",
  "overall_readiness": 8,
  "can_generate": [1,2,3,5],        // 能做的图编号
  "needs_input": [4,6,7],            // 需要补充素材才能做的图
  "missing_items": [
    {"item": "USB-C接口细节图", "for_image": 4, "importance": "high"},
    {"item": "竞品对比信息", "for_image": 6, "importance": "medium"}
  ],
  "suggestions": ["建议补拍45度角产品图", "建议提供产品尺寸数据"]
}
```

## 三、Step 2 — 整套方案设计（Gemini 方案规划）

### 这一步的核心逻辑

Gemini 不是一张一张独立设计的。它是**先定整体，再拆单张**：

#### 2a. 确定整体风格一致性

```
整体风格决策：
├── 色调基准：基于产品本身颜色 + 品牌色 → 确定主色调
│   例：Excitat 蓝色边框 + 灯笼音箱暖光 → 深蓝/暖橙双色调
├── 氛围基准：基于产品品类 + 目标人群 → 确定情绪方向
│   例：户外音箱 → 户外冒险/派对欢乐/温馨露营
├── 排版风格：标题字体风格、文字位置习惯、图标风格
│   例：白色粗体无衬线、文字在上1/3、线性图标
└── 关联线索：7张图之间的视觉连贯元素
    例：每张图都有「RGB 光晕」作为视觉锚点
```

#### 2b. 按图片类型匹配 Prompt 框架

每种图片类型有自己的 prompt 结构模板：

| 图片类型 | Prompt 重点维度 | 适合的生成模型 |
|---------|---------------|-------------|
| Hero（主图） | 产品主体、材质、光影 | Flux 2 Pro（写实） |
| Lifestyle（场景） | 环境、人物、情绪 | Flux 2 Pro（场景） |
| Benefit（卖点） | 功能可视化、动态效果 | Flux 2 Pro + 文字用 Ideogram |
| Detail（细节） | 微距、材质、工艺 | Flux 2 Pro（微距） |
| Specs（参数） | 产品全貌、标注空间 | Ideogram V3（带文字+图标） |
| Differentiator（对比） | 多场景拼接、独特卖点 | 模板拼接 + Flux 2 Pro |
| Trust（信任） | 包装、场景、情感 | Flux 2 Pro（场景） |

#### 2c. 生成每张图的精细 Prompt

对于每张图，Gemini 输出一个结构化 prompt 包：

```json
{
  "image_number": 3,
  "image_type": "benefit",
  "style_consistency_anchors": ["dark background", "RGB glow accent", "white bold title"],

  "prompt_photorealistic": "完整的 Flux prompt，专注画面，不含文字...",
  "prompt_with_text": "完整的 Ideogram prompt，含文字渲染指令...",

  "text_overlay": {
    "headline": "40W Dual-Driver Power",
    "subtext": "Room-filling stereo sound",
    "position": "top-center",
    "style": "white, bold, 52px, uppercase"
  },

  "generation_strategy": "flux_pro_base + ideogram_text_overlay",
  // 或 "ideogram_direct"（Ideogram 直接出图含文字）
  // 或 "flux_pro_base + html_template_overlay"（模板贴文字）

  "reference_images": ["用户上传的第2张图作为产品参考"],
  "negative_prompt": "...",
  "quality_targets": {
    "min_score": 7,
    "key_criteria": ["product_accuracy", "mood_atmosphere"]
  }
}
```

## 四、Step 3 — 品牌框生成（新方案）

### 当前问题
你截图中的 Excitat 品牌框非常精美 — 蓝色装饰性边框带有藤蔓/卷轴花纹角饰，
EXCITAT 红色艺术字在右上角，genius 标签在左上角。这不是 CSS 能做的。

### 新方案：品牌框独立生成 → 透明图层叠加

```
品牌框生成流程：
│
├── 方案A：AI 生成品牌框（推荐 Phase 0 先试）
│   1. 把现有产品图中的品牌框截取出来作为参考
│   2. 用 img2img / ControlNet 方式让 AI 生成「只有边框、中间透明」的装饰框
│   3. Prompt: "decorative ornamental border frame, blue scrollwork vines,
│      baroque corner flourishes, transparent center, PNG with alpha..."
│   4. 或者用 Ideogram 直接生成含 EXCITAT 文字的边框
│   5. 输出：一张 PNG 透明底的品牌框
│
├── 方案B：提取现有品牌框 → 参考垫图
│   1. 从你现有的 emag 产品图中，提取品牌框部分
│   2. 去掉中间产品内容，保留边框图层
│   3. 用这个作为 IP-Adapter 的参考图（style reference, scale 0.3-0.5）
│   4. AI 可以生成风格一致但颜色/细节可调的新框
│
├── 方案C：设计固定品牌框模板 → PSD/Figma 图层
│   1. 请设计师做一个标准品牌框（或你自己用 Figma）
│   2. 导出为透明 PNG
│   3. 程序直接叠加，不需要 AI 生成
│   4. 最简单最可控，但缺乏灵活性
│
└── 最终合成流程（不管哪种方案）：
    1. AI 生成产品场景图（中间区域）
    2. 品牌框图层叠加在上面
    3. 根据场景图的主色调，微调框的色彩（色相偏移）
    4. Playwright/Canvas 合成最终图
```

### 关于 LoRA 训练品牌框风格

可行，但建议 Phase 1 再做：

- LoRA 训练需要 15-30 张品牌框样本图
- 训练时间 ~30分钟（fal.ai 上可以直接训练）
- 训练后可以用 trigger word 生成「风格一致但内容不同」的框
- 适合：你有很多不同颜色/风格变体的品牌框需求时
- Phase 0 先用方案 A（AI 直接生成）+ 方案 B（垫图）验证效果

## 五、Step 4 — 图片生成流程

### 模型路由策略

```
每张图进入生成时，按这个逻辑选模型：

if (图片需要精准文字渲染 && 文字量 > 3个词) {
  → Ideogram V3 直出（文字+画面一起生成）
  → 备选：Flux Pro 生画面 + HTML模板贴文字
}
else if (图片是写实场景/产品/人物) {
  → Flux 2 Pro（主选）
  → Flux Ultra（Hero图/重要图追加生成做对比）
}
else if (图片是参数/对比等信息密度高) {
  → Flux Pro 生底图 + HTML 模板叠加文字/图标
}

每张图同时用 2-3 个模型生成 → 后续评审选最好的
```

### 生成参数

```
标准参数：
- 分辨率：1024×1024（生成后可通过 Real-ESRGAN 放大到 2048×2048）
- 引导强度：Flux 默认即可
- 采样步数：Flux Pro 自动 / Schnell 4步
- seed：记录，方便复现和微调
```

### 如果有产品实拍图 → img2img 模式

```
当用户提供了高质量产品实拍图时：
1. 实拍图作为 ControlNet/IP-Adapter 的输入
2. prompt 控制场景/背景/氛围
3. 产品外观保持一致（这是写实路线的关键优势）

fal.ai 支持的方案：
- Flux Redux（图生图变体）
- IP-Adapter（风格迁移，保持产品外观）
- ControlNet Canny/Depth（保持产品轮廓，换背景）
```

## 六、Step 5 — AI 评审流程

### 谁评审？

```
评审分两轮：

第一轮：AI 自动评审（Gemini Vision）
├── 输入：生成的图片 + 原始 prompt + 目标要求
├── 评分：7个维度 × 1-10分
├── 输出：通过/不通过 + 具体反馈
└── 阈值：Overall ≥ 7 通过，< 7 需要迭代

第二轮：人工审核（你）
├── 查看 AI 评审报告 + 实际图片
├── 判断：商业可用性、品牌一致性、细节准确性
├── 标记：通过 / 微调 / 重做
└── 反馈：具体的修改意见（文字描述）
```

### 评审维度详解

```
1. Visual Quality (视觉质量)
   - 是否清晰？有没有 AI artifact（手指变形、纹理异常）？
   - 光影是否自然？颜色是否准确？

2. Product Representation (产品还原度)
   - 看起来像不像一个真实的蓝牙灯笼音箱？
   - 如果有实拍参考图，和实物像不像？

3. Mood/Atmosphere (氛围感)
   - 整体情绪是否符合预设？（暗调、高端、RGB光效）
   - 与标杆（那套蓝牙音箱灯 Amazon 图）的差距？

4. Text Rendering (文字质量) — 仅限含文字的图
   - 文字是否可读？有没有拼写错误？
   - 字体风格是否与画面融合？

5. Composition (构图)
   - 主体位置是否合理？留白是否够贴文字？
   - 视觉引导线是否自然？

6. Commercial Viability (商业可用性)
   - 直接放到 Amazon/Ozon listing 上，能不能用？
   - 是否需要大量后期修改？

7. Benchmark Proximity (标杆接近度)
   - 和标杆图的质量差距？
   - 0=完全不像，10=可以直接替代
```

### 不通过怎么处理？

```
不通过后的迭代策略（3种模式，按严重程度选择）：

模式1：Prompt 微调重生成（问题小）
├── 场景：整体还行，但某个细节不对（光线太亮、角度偏了）
├── 做法：保留原 prompt 的 80%，调整有问题的部分
├── 保留原 seed，只改关键参数
└── 重新生成 1-2 次

模式2：Prompt 重写 + 反馈注入（问题中等）
├── 场景：方向对但质量不达标
├── 做法：把评审反馈（AI 的 + 人的）作为额外 context 喂给 Gemini
├── Gemini 重新设计这张图的 prompt
├── Prompt 模板：
│   "上一版生成的图片存在以下问题：{问题列表}
│    请重新设计 prompt，重点解决这些问题。
│    保持与其他 6 张图的风格一致性。"
└── 换个模型也试试（比如 Flux Pro 不行换 Ideogram）

模式3：方案层面调整（问题大）
├── 场景：这张图的概念/构思就不对
├── 做法：回到 Step 2，重新设计这张图的方案
├── 可能需要更换图片类型策略
└── 比如「对比图效果不好 → 改成用户评价截图拼接」
```

### 评审看什么？

```
AI 评审时同时看：
1. 生成的图片本身（视觉分析）
2. 原始 prompt（检查是否执行到位）
3. 目标要求（检查是否满足商业需求）

Gemini 的评审 Prompt：
"你同时收到了：
 - 一张 AI 生成的电商产品图
 - 生成这张图时使用的 prompt
 - 这张图的设计目标和要求

 请对比分析：
 1. 图片是否忠实执行了 prompt 的要求？
 2. 图片是否达到了设计目标？
 3. 如果不达标，具体是 prompt 的问题还是模型的问题？
 4. 给出具体的改进建议（针对 prompt 的修改）"
```

## 七、Step 6 — 对比图的特殊处理

### 竞品对比图需要什么？

```
对比图生成需要额外输入：
1. 竞品产品名称和品牌
2. 竞品的关键参数（功率、电池、防水等级等）
3. (可选) 竞品图片 — 用于视觉对比

对比图的生成方式：
├── 方案1：纯 AI 生成对比图（风险：竞品产品外观不准确）
├── 方案2：HTML 模板拼接（推荐）
│   - 左边：我们的产品图（AI 生成或实拍）
│   - 右边：竞品产品图（从竞品 listing 截取，或 AI 生成通用外观）
│   - 中间：参数对比表格（HTML 渲染）
│   - 底部：✓/✗ 标记
└── 方案3：让 Gemini 设计一个「不直接展示竞品」的差异化图
    - 比如只展示「我们有而别人没有」的功能
    - 避免版权和法律风险
```

## 九、关于设计类 Skill 的考虑

当前流程确实涉及比较专业的设计知识（品牌框设计、色彩搭配、排版规范）。
建议在系统跑通后，可以创建一个专用 Skill：

```
可能需要的 Skill：
├── ecommerce-listing-generator
│   ├── 集成上述所有步骤的最佳实践
│   ├── 内置各类图片的 prompt 模板库
│   ├── 内置品牌框生成/合成逻辑
│   ├── 内置评审标准和迭代策略
│   └── 一个命令生成整套图
│
└── 但这是 Phase 2+ 的事情
    Phase 0 的目标是先跑通单次流程，验证效果
```
