# eMAG 详情页生成前置研究目标

## 1. 我的需求

- 先把 eMAG 产品详情页的生成前置研究跑通，重点对象是“详情 HTML”，不是图片。
- 基于 eMAG 官方限制、真实商品详情样本、以及现有 Agent / PPT / Open Design 经验，整理出一套可执行的生成输入。
- 为后续 Agent 化做准备：让用户输入必要产品信息后，系统能稳定生成合规、可读、可继续美化的 eMAG 详情页 HTML。

## 2. 限制要求

- 以“先跑通”为主，不做过重实现，不在当前阶段追求完整生产系统。
- 研究范围优先放在：
  - eMAG 官方对详情 HTML、图片、描述内容的限制。
  - 真实商品详情 HTML 的结构规律，尤其是手机端呈现。
  - 现有样本中哪些是平台硬限制，哪些只是卖家的常见写法。
- 不把当前抓到的样本当成唯一标准，需要明确还有哪些优化空间可以让详情页更美观。
- 未来工作流设计需要吸收：
  - Agent Platform 里 PPT Agent 的前置读取逻辑。
  - Open Design / `DESIGN.md` 的设计系统注入方式。
  - Proma 或相近方案里“先读规则、再规划、再生成”的流程。
- 遇到验证码、权限、网络卡顿、或明显需要人工审批的点时暂停，不硬跑。
- 后续研究和输出尽量短、准、可执行，避免在目标定义上继续消耗 token。

## 3. 确定完成结果的标准

- 已确认并读懂 eMAG 官方对详情页 HTML / 图片 / 描述的主要限制，并形成简明结论。
- 已抓取并保存一批真实 eMAG 商品的详情 HTML，样本足够支持结构分析和模板归纳。
- 已输出一份结构化总结，至少回答：
  - 详情页允许或常见使用哪些 HTML 结构。
  - 图片、GIF、宽度、排版、移动端展示分别受什么影响。
  - 哪些是硬限制，哪些只是当前样本的习惯写法。
  - 在限制内还能怎么做得更好看。
- 已整理出一版更好的电商详情页 HTML 编写 SOP，能指导后续模板化。
- 已给出一版未来 Agent 工作流草案，说明如何把：
  - 产品输入
  - 规则读取
  - 设计文档 / 品牌案例读取
  - 模板规划
  - HTML 生成与后续修改
  串成一个能落地的流程。
