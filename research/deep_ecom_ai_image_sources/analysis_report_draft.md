## Main Finding

The strongest current direction is not pure text-to-image product generation. The practical stack is:

1. Real product source as truth anchor.
2. Structured product analysis or ProductTruthPack.
3. Slot-specific creative brief.
4. Model routing by task.
5. Review gates and deterministic expansion.
6. Platform-specific upload/export.
7. Performance feedback loop.

Pure AI product images still fail on label fidelity, exact dimensions, fit/function, reflective/transparent materials, and buyer trust. The winning workflows use AI aggressively for secondary images, lifestyle scenes, infographics, ad variants, UGC/video seeds and background/context generation, while keeping main/identity-critical product assets anchored in real photos or cutouts.

## Framework Families

### 1. Amazon Image-Set Compiler

Evidence: `M011`, `M023`, `S066`, `S107-S110`, `S171`, `S200`, `S213-S215`.

Input:

- Real product photo set: front, side, back, close-ups, hand/scale image.
- Listing bullets, customer pain points, reviews/Rufus questions.
- Slot type: main, lifestyle, benefit, feature, comparison, instruction, dimension, A+.

Workflow:

- Use real product references.
- Tell model the final Amazon slot and mobile readability requirement.
- Generate slot-specific candidates.
- QA against actual product and Amazon policy.
- Test one image change at a time.

Boundary:

- Seller discussions are cautious about AI main images.
- AI lifestyle/secondary images are more accepted.
- Amazon Ads tools are official for ad creatives, but do not automatically settle listing main-image policy.

### 2. Shopify Catalog Pipeline

Evidence: `M030`, `S082`, `S094`, `S095`, `S156`, `W022`.

Input:

- Shopify catalog data.
- Product images and variants.
- Brand spec: colors, fonts, photography recipes.
- Reference image arrays.

Workflow:

- Maintain a brand logic layer.
- Generate with indexed references and exact text constraints.
- Upload through Shopify staged upload and `fileCreate`.
- Poll file status.
- Audit every batch for drift.

Boundary:

- Shopify image display/CDN/downscaling can degrade detail.
- Apparel/fashion detail shots remain essential.
- App-store/tool claims need live QA.

### 3. Ozon/Wildberries Card Factory

Evidence: `M013`, `M014`, `M035`, `S116-S122`, `S206-S209`, `W002-W004`, `W027-W029`.

Input:

- Real product photo or URL.
- Category, benefits, objections, SEO terms.
- Marketplace card format.

Workflow:

- Realistic/neutral main card.
- Secondary cards for benefits, dimensions, lifestyle, comparison and infographics.
- Use model router:
  - product-preserving edit for product/white background
  - scene model for lifestyle
  - text-strong model for infographic
  - video model for 5-second preview/live photo

Boundary:

- Ozon official seller content explicitly says cards must include real photos.
- Russian guides repeat realistic main image plus stylized secondary cards.
- Do not treat AI-only card sets as safe by default.

### 7. Reference-Lock and Video-Agent Commercial Workflow

Evidence: `M042`, `M043`, `S068`, `S069`, `S084-S086`, `S091`, `S092`, `W037-W039`.

- Real product photo.

### 8. Full-Set Listing and Detail-Page Factory

Evidence: `M044`, `M046`, `M047`, `S238-S256`, `W040-W048`.

Input:

- Product photo or ASIN/product URL.
- Product bullets/specs/selling points.
- Brand identity: colors, logo, style reference.
- Slot map: main, lifestyle, benefit, feature, comparison, dimension, A+, mobile, detail-page sections.

Workflow:

- Convert product data and slot map into per-image creative briefs.
- Generate or edit each slot with GPT Image 2/Nano Banana 2/Coze/ComfyUI/workflow tool.
- Apply global brand instructions and per-image edit/regenerate.
- Use deterministic text/graphics overlays where exact claims matter.
- Export to Amazon A+, Shopify, cross-border marketplace detail pages or Chinese ecommerce cards.

Boundary:

- Seller discussions consistently say generic single-image generation is not enough.
- The value is a coordinated visual system with slot strategy, consistency, editability and compliance review.
- Direct Bilibili video capture is still needed for exact node graphs and prompts.

### 9. Agent/MCP Prompt-as-Code Workflow

Evidence: `M048`, `M049`, `M050`, `S257-S270`, `W049-W055`.

Input:

- Product brief or product image.
- Prompt template library by slot/category.
- Agent runtime: Codex, Claude Code, Cursor, MCP or Skill.
- Model router: Nano Banana 2/Pro, GPT Image 2, Midjourney, Flux/Seedream.

Workflow:

- Agent selects or rewrites prompt from a categorized prompt bank.
- MCP/Skill routes image generation/editing to the selected model.
- Prompt, model, date, input refs and output path are logged.
- Human or VLM/OCR gate checks product identity, text and compliance.
- Approved prompts become reusable slot templates.

Boundary:

- Prompt libraries move fast and can be stale, duplicated or spammy.
- X-origin prompts are discovery inputs. They should be benchmarked on real SKUs before entering production.
- Generic MCP servers need ecommerce-specific metadata, review gates and export logic added.

### 11. No-Prompt Agent and Native Marketplace Media Tooling

Evidence: `M053`, `M054`, `S292`, `S294`, `S296-S299`, `W069-W074`.

Input:

- Product photos and platform/category selection.
- Existing card/PDP media if using WB/Ozon native tools.
- Optional product name, selling points, competitor image/style reference.

Workflow:

- No-prompt agent infers prompt plan and slot briefs from product/category/platform.
- Generates full matching main images, secondary images, A+ or detail-page assets.
- Native WB/Ozon tooling handles background/model replacement, virtual model generation, quality improvement, 3:4 crop, video covers, rich content and A/B tests.
- Final output is accepted only after marketplace media requirements and product-truth checks.

Boundary:

- "No prompt" does not mean no workflow; it means prompt orchestration is hidden.
- Platform-native tooling is useful because it sits closer to compliance and seller workflow, but it still has strict input requirements, limits, moderation and category restrictions.
- Credit/refund promises from external tools are evidence that product mismatch is common, not proof that mismatch is solved.

### 12. Coze Two-Branch Main/Detail Pipeline

Evidence: `M055`, `S284`, `S287`, `W064`, `W066`.

### 13. Self-Hosted Cleanup and SKU-Connected QA

Evidence: `M057`, `M058`, `S300-S304`, `W075-W077`.

Input:

- Raw phone product photo.
- SKU/product-card facts.
- Category/platform/brand rules.
- Buyer objections and slot plan.

Workflow:

- Use deterministic cleanup first: background removal, alignment, resize, edge/artifact cleanup.
- Use AI for enhancement, lighting, backgrounds, context and variants.
- Tie image generation to SKU attributes and rules.
- Review consistency across multiple outputs before upload.

Boundary:

- The strongest community signal is that consistency, not beauty, is the bottleneck.
- A catalog factory should verify color/material/shape/logo/package/accessories across all images of a SKU.

### 14. Wrapper, Product Hunt and Commercial-Readiness Layer

Evidence: `M060-M064`, `S311-S325`, `W083-W091`.

Input:

- X/aggregated launch and benchmark signals.
- Product Hunt/indie tool launches.
- Website URL, product photo, template/preset choice or product-page input.
- Tool/license/watermark/commercial-use state.

Workflow:

- Use X/Product Hunt to discover current model/tool directions.
- Classify wrappers by input pattern: URL-to-brand-ad, one-photo-to-scenes, product-photoshoot templates, product extraction/mockup prep, image-to-video.
- Promote only the reusable method, not the marketing claim.
- Before use, check product fidelity, watermark, commercial license, marketplace rules and official model constraints.

Boundary:

- Wrapper pages are good for market mapping and workflow taxonomy, but weak evidence for output reliability.
- Commercial readiness is not just image quality; it includes watermark, rights, policy, product truth and repeatability.

### 15. Evaluation and Spec-First Production Layer

Evidence: `M066`, `M067`, `S328-S331`, `W093-W094`.

Input:

- Model candidates: GPT Image 2, Nano Banana 2, Midjourney, wrappers.
- Prompt categories and source image matchups.
- Rubric: product identity, text/OCR, style, adherence, detail, material, marketplace safety.
- Templates and model options.

Workflow:

- Build benchmark prompt/source set around real ecommerce failure modes.
- Run models through a resumable stateful pipeline.
- Judge with hidden labels or model-as-judge, plus human spot review.
- Convert winning patterns into spec-first YAML templates.
- Validate/preflight unsupported options and log all runs to local ledger.

Boundary:

- Benchmarks must be task-specific. A generic image leaderboard does not prove marketplace SKU reliability.
- Spec-first templates improve repeatability, but they still need product references, OCR and marketplace QA gates.

### 17. Seller-Platform Governance Layer

Evidence: `M070-M072`, `S337-S346`, `W099-W105`.

Input:

- Marketplace/listing channel: Amazon PDP, Amazon Ads, Shopify PDP, Meta catalog.
- Seller source images and generated image assets.
- Platform image rules and feed behavior.

Workflow:

- Generate and upload images only after slot classification.
- Monitor live PDP/ad feed images after upload.
- Detect platform-initiated image changes or wrong feed selection.
- Preserve source-photo archive and screenshots for escalation.
- Use feed override or gallery-order rules when different channels need different lead images.

Boundary:

- Image generation quality is not enough. Platform systems can alter, choose or export images in ways that break product truth.
- Amazon needs post-upload PDP image monitoring. Shopify needs feed/channel mapping and bulk-app workflow control.

## Model Routing

### Nano Banana Pro / Nano Banana 2

Use for:

- Product-reference edits.
- Amazon listing secondary images.
- Product campaign fanout.
- Technical infographics when grounded by references.
- n8n automation when product photo is clear.
- API/batch image/edit workflows through Google AI Studio or Gemini API when current official docs support the route.

Risks:

- Version/provider routing instability.
- Nano Banana 2 may not equal Nano Banana Pro in product-photo quality.
- Exact dimensions/internal structures can hallucinate.
- Official Google docs now position Nano Banana 2 for subject/object consistency, text/localization, native aspect ratios and 512px-to-4K resolution tiers, but that does not remove product/claim QA.

### GPT Image 2

Use for:

- Text-heavy ecommerce images.
- Infographics and comparison cards.
- Multi-language static ads.
- Shopify/API catalog pipelines.
- Prompt/template libraries and batch API workflows.
- Officially bounded image generation/editing with text and image inputs, image output and high-fidelity image references.
- Slot-led full listing sets: packshot, hero, lifestyle, comparison, infographic and localized static ads when reference/product truth is supplied.

Risks:

- Official capability, pricing and snapshot must be verified before implementation.
- Product detail preservation still needs reference and QA.
- Wrapper sites make claims that may exceed real API behavior.
- The current official model page records snapshot `gpt-image-2-2026-04-21`; production should pin or log snapshot/version where possible.

### Midjourney V8/V8.1

Use for:

- Premium editorial product concepts.
- Moodboards.
- Fast commercial style exploration.
- Non-compliance-critical ad key visuals.
- Style-reference and moodboard-led visual direction before product-preserving edit/composite.

Risks:

- Not the best core for exact SKU, label or platform-compliance imagery.
- Official V8/V8.1 pages emphasize `--raw`, HD, style references and moodboards; Omni-Reference is useful context but is older/experimental and should be validated per current model version.

### Coze / ComfyUI / Chinese Workflow Tools

Use for:

- Batch main-image and detail-page generation.
- Workflow-canvas orchestration around product image, selling points and hot-image references.
- Self-hosted or semi-self-hosted template factories.
- Feishu/multidimensional table as batch-control surface for image/video generation rows.

Risks:

- Current Bilibili evidence has improved to direct BV/API capture for several leads, but still needs full video watching and screenshot extraction.
- Detail pages are long and text/spec-heavy; generated claims require OCR, spec checks and layout review.

### Wildberries / Ozon Native Tools

Use for:

- Platform-native background/model replacement.
- Virtual model generation for clothing.
- Image quality improvement, 3:4 crop, video covers, rich content and A/B testing.
- Lower-friction compliance workflow for existing seller cards/PDPs.

Risks:

- Native tools do not bypass moderation or media requirements.
- WB Photostudio has country/tariff/category/input-photo restrictions.
- Ozon image editor has effect-specific requirements and daily limits.

### FLUX / SDXL / ComfyUI

Use for:

- Backgrounds and studio-shot generation.
- Self-hosted or low-cost systems.
- Shopify app prototypes.
- Hardware-constrained internal tools.

Risks:

- Text rendering and product label fidelity often weaker than GPT Image 2.
- More engineering required for reliable product truth.

## Practical Architecture Recommendation

For an internal ecommerce image factory, the evidence points to this structure:

1. ProductTruthPack:
   - original photos
   - cutout
   - multi-angle refs
   - close-up details
   - dimensions/materials
   - marketplace rules

2. CreativeBrief:
   - marketplace
   - image slot
   - buyer question/objection
   - text/copy
   - brand style
   - language/country

3. ModelRouter:
   - product-preserving edit
   - infographic/text render
   - lifestyle/background
   - video/UGC
   - deterministic composite/layout

4. QA Gates:
   - product geometry
   - logo/text/OCR
   - material/color
   - dimensions/specs
   - platform policy
   - mobile readability

5. Expansion:
   - formats/aspect ratios
   - languages
   - marketplace variants
   - campaign variants

6. Export:
   - Shopify staged upload
   - Amazon Ads Creative Asset Library/manual upload
   - Ozon/WB card export
   - Drive/Airtable/gallery

7. Feedback:
   - CTR/CVR
   - seller reviews
   - customer objections
   - Rufus/review mining
   - ad performance signals

## What Still Needs More Evidence

- Direct X/Twitter original posts are still weak because index access is unreliable.
- More direct Bilibili video watching is needed for exact BV IDs, prompts and screenshots.
- More Ozon/WB official policy pages are needed for exact upload rules.
- More real conversion data is needed; many tool pages claim lift but do not prove it.
- Need live output testing against a controlled SKU benchmark before ranking models.

## Provisional Answer

The most defensible production path is a hybrid, product-reference-first system. Use AI for speed and variation, but keep product truth, layout, text and compliance as separate controlled layers.

The strongest small-framework candidates to study further are:

- ProductFlow for self-hosted product/media workbench shape.
- dexfinity-product-ads for Gmail feed -> FAL Nano Banana 2 -> Drive/Sheets multi-client automation.
- static-ads for GPT Image 2 text-in-image static ad pipeline with review gates.
- ai-ads-autopilot for product photo + creator photo -> static ads -> HeyGen UGC video.
- n8n product photography templates for fast workflow automation.

The strongest website/product cases to compare are:

- Amazon Creative Studio / Image Generator.
- Ozon Seller AI media tools.
- Sozdai / Twin AI / FORMIA / Pixorion for Ozon/WB.
- Poify / Tongyi Wanxiang / Qwen API for Chinese batch factories.
- SellerPic / SellShots / Adject / KREV for Product Hunt-style ecommerce creative SaaS.
- Topview / AuraTuner / PixelPanda / ReFramedShot / Aluo / Pic1 for wrapper/tool positioning.
